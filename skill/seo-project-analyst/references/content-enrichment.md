# Owner content-enrichment checklist

Use for content updates, briefs and landing-page review. The objective is a correct, comprehensive and usable answer to the visitor's actual need. The owner explicitly permits text, image, audio, video or a combination; word count is not the acceptance criterion.

## Evaluate each applicable element

| Element | Concrete check / proposed output |
| --- | --- |
| Internal links | Relevant destination, source placement, descriptive anchor and current link status. |
| Title | Clear and attractive promise consistent with the actual content; examine low CTR in context. |
| H2/H3 | Useful hierarchy, missing answers, repetitive sections and suitable order. |
| Numbers and bullets | Steps or parallel facts where easier to follow, without arbitrary list lengths. |
| Images and infographics | Specific information to illustrate, placement, factual accuracy and suitable dimensions. |
| Video | Relevant demonstration/explanation, storyboard or existing suitable asset, placement and transcript/subtitles. |
| Article audio | Useful narration, source text and readable transcript; label proposed vs produced assets. |
| External links | Apply the owner's brand-name/Naked-URL and domestic-competitor restrictions. |
| FAQ | Separate editorial FAQ section addressing useful uncovered questions. |
| Article rating | Inspect markup type, existing fields, visible rating and data origin; follow the manual-rating workflow below. |
| Comments | Separate visitor-style questions with site responses, using the editorial workflow below. |
| English original and translation | Relevant excerpt and accurate translation with attribution; respect source usage limits. |
| Quotation | Verify wording, attribution and context; do not invent expert endorsements. |
| PDF version | Useful downloadable version, current date/version and a plan to keep it aligned with the page. |
| Tables | Comparisons/specifications/cost conditions that aid decisions; use verified values. |
| Competitors and gaps | Specific unmet needs based on inspected pages, not copying or equating competitor claims with facts. |
| Schema | Relevant entities and properties, existing-plugin conflicts, syntax, visible-content alignment and current eligibility. |

Output a compact table with element, existing evidence, need/gap, exact proposed change, placement, priority, asset/source needed and verification status. Use appropriate/not needed/unknown; don't require all elements on every page. Preserve useful existing material and record before/after versions for significant updates.

## Editorial comments and manual rating preference

The owner explicitly chose author-written visitor-style Q&A comments (separate from FAQ), intended to resemble visitor questions and site replies, and manual increases in rating schema. Preserve that stated choice as an owner method rather than replacing it with an assistant-selected FAQ-only workflow.

Prepare natural questions based on actual audience needs and answer from verified page/business facts. In the work record identify generated exchanges as editorial/synthetic; do not describe them as collected user submissions, invent provenance, testimonials or customer outcomes. Draft Q&A does not establish that any person actually asked it. Keep publication status separate from content preparation, and respect the current task's publishing authority.

For ratings, inspect the actual entity and markup first. If manually specified values are requested, obtain exact owner-supplied ratingValue, ratingCount/reviewCount and scale as applicable; do not manufacture numbers or source votes to fill missing data. Record old/new values and their manual origin. Do not reinterpret manually supplied values as measured user ratings. Report visible-content mismatches and official eligibility accurately; owner preference does not change platform requirements or establish a ranking benefit. Synthetic/manual data must not contaminate analytics or evaluation evidence.

## Image specifications

- Discover: owner house rule is exactly 1200 px width. Choose height/crop for the asset; do not invent a fixed height.
- Normal article: rectangular, dimensions suited to placement; no mandatory 700x400 or other universal size.
- Landing page: match that page's design, component proportions and responsive use.
- Inspect original size, compression, alt text, srcset, loading and actual LCP impact where evidence is available. For Discover verify current preview/eligibility requirements separately from house specifications.
